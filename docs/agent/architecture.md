# Current application architecture

Next.js 14.1.4, React 18.2, and Tailwind 4 alpha are pinned. Pages and route handlers live in [`app/`](../../app/); shared code lives in [`lib/`](../../lib/). Site URLs and dates are centralized in [`lib/site.ts`](../../lib/site.ts) and [`lib/dates.ts`](../../lib/dates.ts).

## Content and layout

- [`lib/wiki/mdx-files.ts`](../../lib/wiki/mdx-files.ts) reads MDX and caches files in memory in production only. Check `isSafeSlug` before using a user-supplied slug for a filesystem lookup. Published blog files use `NN-name.en.mdx` / `NN-name.it.mdx`; notes use `NN-name.mdx`. Blog drafts and entries without a title or valid publication date are excluded from routes, listings, feed, sitemap, and the index.
- [`middleware.ts`](../../middleware.ts) sets the `lang` cookie for the blog; unsupported languages fall back to Italian. The list defaults to English, a post defaults to Italian, and a first request can render with the pre-existing cookie or default. Both languages use the same slug; a missing translation falls back to the available language. Metadata must match the rendered translation. The financial-mathematics note is Italian; other notes are English.
- [`ContentList`](../../app/components/ContentList.tsx) searches in the browser, so `/blog` and `/notes` ship the full public text. [`ArticlePage`](../../app/components/ArticlePage.tsx) shares article rendering and mounts comments after blog articles only; note pages do not show them. [`mdx.tsx`](../../app/components/mdx.tsx) renders trusted repository-owned MDX with KaTeX. `<Table>` data is evaluated with `Function(...)` before conversion to Markdown; never send untrusted input through that path.
- [`EconomyChart`](../../app/components/EconomyChart.tsx) is desktop-only; the fixed-production example and calculations live in [`lib/economy-chart.ts`](../../lib/economy-chart.ts). One-off Python chart scripts are not part of the Next build.
- [`lib/seo.ts`](../../lib/seo.ts) owns canonical URLs and author-written descriptions. Public social previews use `/icon.png`; `/og` remains a landscape image generator. [`next.config.js`](../../next.config.js) redirects `/cv` and preserves trailing-slash behavior site-wide. MathJax loads globally in addition to KaTeX; do not remove it or change visible copy without approval and a before/after UI comparison.

## `/ask`

[`app/api/ask/route.ts`](../../app/api/ask/route.ts) caps questions at 500 characters and applies a per-instance limit of 15/minute/IP. It loads the index and embeds the query, then [`retrieveHybrid`](../../lib/wiki/retrieve.ts) uses BM25 and cosine similarity fused with reciprocal rank fusion (top eight, keyword-only without an embedding). [`selectContext`](../../lib/wiki/passages.ts) selects passages within a 30,000-character budget, keeping a passage from each selected note when possible. The API sends JSON citations on the first line, then Markdown, and aborts on disconnect. Citations represent the notes supplied to the model, not just notes cited in its answer. Private citations have no URL. The profile in the prompt can also answer questions about the owner. See [Data and services](data-and-services.md) for the index and runtime boundary.

## Comments

[`Comments`](../../app/components/Comments.tsx) fetches as the reader approaches the blog section; it does not block article rendering. Thread keys are canonical public paths and are shared across blog translations. Note threads remain stored but are not displayed on note pages. Plain-text posts use a two-step form, keep drafts on failed submissions, and remember the last successfully posted display name on-device. There are no visitor accounts, comment telemetry, or static comment payloads.

[`app/api/comments/route.ts`](../../app/api/comments/route.ts) checks article keys against the public readers and uses no-store responses. POST checks the origin, rate-limits by IP (10 per 10 minutes per instance), caps the body at 16 KiB, validates fields and rejects honeypot hits. Display names and bodies are capped at 20 and 2,000 characters. Expect `201` for a stored comment, `400` for invalid input, `429` for rate limiting, and `503` when the database is unavailable. [`store.ts`](../../lib/comments/store.ts) pages roots newest first and replies oldest first with stable timestamp/ID order. Replies are one level deep; moderated roots keep their replies and remain valid parents. See the [original design](../../SPEC_COMMENTS.md) and [operating notes](../../README.md#public-comments).

## Other server endpoints

- **Newsletter:** [`app/api/newsletter/`](../../app/api/newsletter/) and [`lib/newsletter.ts`](../../lib/newsletter.ts) implement double opt-in. The footer form checks consent and a honeypot; limits are five submissions per 10 minutes/IP and three confirmation messages per hour/address. Only a valid HMAC-signed GET confirmation within 48 hours creates or resubscribes a contact, so mail scanners can confirm links. The check-inbox, confirmed, and expired pages are noindex and not in the sitemap. Keep existing signed GET and one-click POST unsubscribe links valid.
- **Metrics:** [`app/api/posthog/route.ts`](../../app/api/posthog/route.ts) validates eligible blog/note URLs before lookup; no request URL enters HogQL. [`lib/posthog.ts`](../../lib/posthog.ts) runs exactly three fixed queries (site views, site time, article views), with a 60-second cache and last-good fallback. The 25-second upstream timeout leaves room under the 30-second route limit. Do not add one query per page: the provider queues excess concurrent queries. Views include only `$pageview`, including client navigations. Blog lookups use the production URL even on localhost; notes use `baseUrl`, so local note counts are normally zero. The EU `/ingest` rewrites are unused by the browser's direct integration.
